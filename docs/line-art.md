# Line art (vector sprites)

Thin neon line art next to the pixel art. By default every ghost (in play, in LEARN and on the LEARN picker) is drawn from one hand-written SVG, `src/game/art/ghost.svg`, in its own neon colour, and Dot-Man in the maze (play and LEARN) from `src/game/art/dotman.svg` in neon yellow (`#ffe600`). Under Settings → **STYLE = NEON**, pellets are thin circular strokes (power / boss / optional keep a maze-coloured bloom; regular dots are crisp-only — see below), while fruit stays PNG. The HUD lives icons and the store life glyph use the same Dot-Man SVG (baked to a texture, see below). Quarter icons (HUD row, store tile prices, Money Talks fly-outs) use `src/game/art/quarter.svg` in silver (`#c8d0e0`) under NEON/LINED — a faint filled disc, rim, and a minimal left-facing profile + queue hint (hybrid-abstract; not a detailed Washington bust). **LINED** is the same line-art ghosts, Dot-Man, Quarters and stroke-ring pellets with every glow forced to 0 (including UI neon-font bloom). **PIXEL** (all three stored as `pac-rogue.ghost-style.v1`) switches ghosts, Dot-Man and Quarters back to pixel PNGs, turns maze wall glow off, and restores the classic pellet PNGs. The same STYLE setting also selects the UI typeface (NEON/LINED → neon bar-curve, PIXEL → VGA pixel) — see [fonts.md](./fonts.md) — and skins the play HUD **BONUS** meter (NEON/LINED → capsule neon tube; NEON adds glow; PIXEL → 12-slot art-pixel bar; see [bonus.md](./bonus.md)). Dot-Man rotates to face each turn (see below); nothing else is animated yet, but the SVG is parsed into point lists that carry distance along the path, so a later "unspool" (trim the stroke away along its path) needs no data rework.

## Rendering model

- **The canvas matches the screen's physical pixels.** World coordinates stay 800×600. The canvas is 800×600 × `renderScaleFor(window size, devicePixelRatio)` (`src/domain/renderScale.ts`): fit-to-window × device pixel ratio, clamped to 1–4. So a 1080p window gets ×1.8 (1440×1080), a 2× retina laptop ×3, and the 900×700 probe viewport ×1.125. The browser then shows it 1:1 with no resampling. On window resize, `followWindowRenderScale` resizes the canvas.
- **Every scene calls `applyRenderScale(this)` first thing in `create()`.** It sets camera origin 0,0 and zoom = canvas width / 800, and re-zooms on resize. Read pointers with `pointer.worldX/worldY`, never `pointer.x/y`. Use `renderScaleOf(scene)` wherever canvas pixels per world pixel matter.
- **Pixel art uses Phaser's `smoothPixelArt`.** 16×16 textures stay blocky but get clean edges at non-integer scales. Graphics are multisampled, so line art is crisp.
- **Glow** uses Phaser 4's `Glow` filter, as a knockout (glow-only) layer under the crisp art:
  - Vector actors: one glow Graphics per actor, holding the art as an opaque silhouette. The Glow filter only emits where its source is transparent, so the glow stays outside the body and never hazes the eyes. The filter is focused on the art box plus the glow reach, at one texel per canvas pixel. Graphics have no bounds, and without that focus Phaser would filter the whole screen every frame. Strength and reach come from the `?knobs=1` **Ghost glow** / **Ghost glow radius** knobs (defaults 1.6 and 6px). **Ghost line thickness** (stroke as % of the ghost's size, default 6.5), **Line ghost width** (horizontal stretch of the geometry, default 1.16) and **Line ghost height** (vertical stretch, default 1.14) are knobs too. All five go through `ghostLineArtLook` in `src/domain/ghostArt.ts`; changing any of them rebuilds the line-art objects, since Phaser fixes the glow distance at creation.
  - Maze walls: the glow is static, so it is filtered once into a canvas-resolution `RenderTexture` whenever the wall style changes (in `render.ts`). Strength comes from `wallGlowFilter` (`src/domain/wallStyle.ts`), which passes `wallGlow` through as Phaser `outerStrength` (defaults: glow **4**, radius **21px**, thickness **1.5px** under STYLE = NEON). STYLE = PIXEL or LINED forces wall glow off when knobs are not on. With `?knobs=1`, **Wall glow** (0–12) and **Wall glow radius** (0–36) always apply.
  - Pellets: under STYLE = NEON, every pellet kind is a filled circle with a white (or grey optional) core. Regular dots have **no glow** (dense majority; crisp-only for cost). Power, boss, and Lazy Looper optional keep maze-coloured outer bloom (power thicker/larger/stronger; optional muted non-wall glow). Power/optional glows bake into one board-level `RenderTexture` (sequential glow layers, each flushed with `render()` before the shared source Graphics is reused — Phaser queues draw-by-reference) when that glowing set or style changes; eating a regular dot does not rebake. Boss pellets use per-entity glow Graphics so their size/alpha pulse stays live. The glow bake source is a filled disc from `pelletGlowSourceLook`, inset slightly under the crisp edge so knockout bloom starts at/inside the white with no dark gap. STYLE = LINED keeps the same stroke rings with glow/radius forced to 0. STYLE = PIXEL keeps `dot.png` / `power-pellet.png`. Look lives in `pelletStyleFor` (`src/domain/pelletStyle.ts`). With `?knobs=1`, the **Dots** panel can still turn regular-dot glow back on (and exposes extreme ranges for stroke, radius, glow, colours, and per-kind overrides).

Code: `src/domain/lineArt.ts` (parser, pure), `src/game/systems/lineArtRender.ts` (Phaser drawing), and the line-art / neon-pellet branches of `src/game/systems/render.ts`.

## Authoring rules

`parseLineArt` reads a deliberately small SVG subset with plain string parsing, so it runs in node tests. Anything outside the subset throws a `lineArt: …` error at boot. There is no fallback.

- The root must have `viewBox="0 0 W H"`.
- Use `<path>` elements only. Each needs a unique `id` and a `d`. `<circle>`, `<ellipse>`, `<rect>`, `<line>`, `<polyline>`, `<polygon>`, `<use>`, `<text>` and any `transform=` are rejected.
- One subpath per path: no second `M`, and nothing after `Z`. Split shapes into separate ids.
- Keep strokes as strokes. Never "outline stroke" or "expand" them in an editor: the stroke's path is what a future unspool will trim.
- **Path direction is the future unspool order.** Draw each path in the order it should appear.
- `stroke` / `fill`: `currentColor` (the actor's colour, set in code), `none`, or `#rrggbb`. A missing attribute means `none`. `fill-opacity` is a number (default 1). `stroke-width` is ignored (preview only); the renderer uses the Ghost line thickness knob. `stroke-linecap` is ignored too: open strokes always render with round ends, so set `stroke-linecap="round"` on open paths to make the browser preview match.
- Path commands: `M L H V C Q A Z`, absolute and relative. `S`/`T` are not supported. Arc flags must be space- or comma-separated (packed flags like `011` are not parsed).
- Strands are drawn in document order. Fill comes first, then stroke.

Each strand becomes `{ id, points: {x, y, s}[], length, closed, stroke, fill, fillOpacity }` in viewBox units. `s` is the distance along the strand from its start. `rotateLineArt(art, degrees)` rotates square art clockwise about its centre (exact for quarter turns).

## Adding a vector actor

1. Put the SVG under `src/game/art/` and parse it once with `parseLineArt` (`import svg from "./x.svg?raw"`, like `ghostLineArt.ts`). Add a test that pins its strands.
2. Map its drawable id in `render.ts`: `LINE_ART_BY_DRAWABLE_ID` (art + colour). The four ghosts share `GHOST_LINE_ART` with colours blinky `#ff5a5a`, pinky `#ff9ce6`, inky `#5ff2ff`, clyde `#ffb852`.
3. Decide when it is vector in a pure domain rule, like `lineArtGhostKinds(style, presentKinds)` in `src/domain/ghostArt.ts`. `PlaySim` and `LearnSim` (both `setGhostStyle`, called by their scenes from the stored setting) send the matching ids as `lineArtDrawableIds`, and `PlaySim.snapshot().lineArtGhosts` exposes them to probes. `render.ts` only acts on what it is told; with the option absent everything stays pixel art. Static pictures outside the maze (the LEARN picker) use `addGhostIcon` from `render.ts`.

Translucent fills (the body's 0.25 tint) sit on an opaque layer of the maze background colour, so nothing behind a line-art ghost (Dot-Man, pellets) shows through. Frozen ghosts recolour the line, fill and glow icy white (`#e6f6ff`; the pixel freeze tint would read as Inky's cyan). Hunter-frightened ghosts recolour them light blue (`#6f7bff`, brighter than the default walls), blinking back to their own colour in the last second like the pixel sprite. The eyes stay white. Dimming uses alpha. Warp-glide afterimages are vector copies without glow.

## Dot-Man

`dotman.svg` is one pipe folded on itself, radiant-heat style: an outer ring (r 44) from the upper lip round the back, a U-bend in the lower lip, a middle ring (r 28) back to the upper lip, a second U-bend, and an inner ring (r 12) ending at the lower lip. The resting mouth is open 140° (±70° half-angle) to the right; both pipe ends use `stroke-linecap="round"` (and `lineArtRender` fills matching end disks, since Phaser Graphics strokes are butt-capped). The rings are 16 units apart, so at one tile (17px) the gaps stay open at a 1x render scale. Under the pipe sits an unstroked `body` pie at 0.2 fill. Like the ghost body, it is opaque in the glow layer, so the glow stays outside the silhouette instead of filling the pipe gaps. The whole stroked pipe stays inside the 100×100 box, so Dot-Man is no bigger than the pixel sprite and fits between the walls.

- **Chomp.** While moving, the mouth half-angle walks open → mid → closed → mid on the same distance beat as the pixel frames. Defaults: speed 1.25× (one beat every 9.6 px; 1× = 12 px), open 70°, closed 5°. `?knobs=1` → **Dot-Man chomp**, **Mouth open**, **Mouth closed** dial them; closed is clamped below open. Radii and ring spacing stay fixed; every lip ray moves together so the spiral opening expands/contracts like a spring (`src/domain/dotManMouth.ts`). Idle holds the open pose. `dotManLineArt(facingDeg, mouthHalfDeg)` composes mouth art + `rotateLineArt`.
- **Turns.** The mouth rotates to face the move direction: a quarter turn the short way in `DOTMAN_TURN_MS`, a reversal clockwise through 180° in `DOTMAN_REVERSE_MS`, both easing out (`src/domain/dotManTurn.ts`; a new facing mid-turn retargets from the angle shown). Cached per whole facing degree and mouth tenth; redraws both the crisp art and the glow source rather than rotating the filtered Graphics. Rotation keeps `s` (unspool order) in every direction.
- **Icons.** `addDotManIcon` (`render.ts`) bakes the right-facing art at the mid chomp half-angle (`DOTMAN_MOUTH_ICON_HALF_DEG`, halfway between open and closed) and its glow into a texture once per STYLE, size, render scale, backdrop and mouth angle, so the HUD lives icons and the store life glyph are plain images that sit in containers and tween like the pixel sprite. PIXEL keeps the PNG.
- **Look.** `playerLineArtLook` (`src/domain/ghostArt.ts`) uses the ghost glow knobs, a fixed 6.5% line and no stretch.
- **Effects.** Wall-pass and invulnerability tints recolour the line the way the pixel sprite's texture tint does (`tintedColor` in `src/domain/playerTint.ts`). The turn flash brightens it and scales the crisp art; the glow keeps its built size, because a scaled filtered Graphics overshoots the art. The tunnel twin is a second glowing copy. Warp-glide and Speed Burst afterimages are glow-less copies. The revive splash is a glow-less copy, since it starts screen-sized. Under STYLE = NEON or LINED, when Dot-Man eats a regular or optional pellet, a gum-stretch FX draws from the pellet into Dot-Man’s world center (chasing him): the strand thins with ball ends as Dot-Man moves away, then the far ball snaps in (`src/domain/pelletAbsorb.ts`, `src/game/scenes/pelletAbsorb.ts`). Defaults: 10ms, stretch share 0.10, mid thin 0.95, near shrink 0.10, suck ease 3.25; mid-strand fill fades to 0 over the absorb. With `?knobs=1`, the **Dots** panel exposes Absorb FX (on/off), duration, stretch share, mid thin, near/far shrink, and suck ease. Power/boss pellets and ghost-harvest eats skip it; PIXEL keeps the instant vanish.
- `PlaySim.snapshot().lineArtPlayer` reports it to probes.

## Quarters

`quarter.svg` is a 100×100 coin: unstroked `body` disc (`fill-opacity` 0.22), open stroked `rim`, and two open strokes for a left-facing `profile` + tiny `queue`. Colour is silver `QUARTER_LINE_ART_COLOR` (`#c8d0e0`) set in code; the SVG uses `currentColor`.

- **Icons.** `addQuarterIcon` (`render.ts`) bakes the art + glow into a DynamicTexture once per STYLE, size, render scale, backdrop and look (same container-safe bake as `addDotManIcon`). PIXEL keeps `art/other/quarter.png`. Used by the play HUD Quarter row, store tile price coins, and Money Talks spend fly-outs.
- **Look.** `quarterLineArtLook` (`src/domain/ghostArt.ts`) reads dedicated Visuals knobs **Quarter glow**, **Quarter glow radius**, and **Quarter line thickness** (defaults: glow **0.6**, radius **5px**, thickness **6%**). No width/height stretch. With knobs off, NEON keeps the default glow and LINED/PIXEL force glow off (`styleUsesGlow`). `PlayScene.applyKnobTuning` pushes the live look via `setActiveQuarterLook`, rebuilds the HUD icons (kept visible under `?knobs=1`), and recreates an open store overlay so tile price coins match. Resuming from the pause menu after Settings → STYLE also rebuilds Quarters (same as lives icons).
- **Gate.** `lineArtQuarter(style)` is true for NEON and LINED; `PlaySim.snapshot().lineArtQuarter` exposes it to probes.

Collision never depends on the drawing: every ghost catches with the same body circle (`Drawable.radius = ghostRadius()`, set in `PlaySim`), so glow, thickness and width are visual only (pinned by the PlaySim "ghost style" tests).
