# Enhanced upgrades: one-shot plan

## Goal

Add "enhanced" versions of all 27 upgrades, a reworked store (two one-time life tiles, two new-ability tiles, a trade tile and an enhancement tile; first store has only lives and abilities), the base-value changes the design requires, and an enhanced toggle on the Learn page (last). Design source of truth: [enhanced-upgrades.md](./enhanced-upgrades.md) (per-upgrade numbers, decisions). This plan is the how.

- Store: `src/domain/store.ts` (`StoreSlot` = life | upgrade | swap, `createStoreState`, `storeStep`, `promptView`), layout `STORE_MAZE_ASCII` in `mazeLayouts.ts` (glyphs `L`,`U`,`S`; currently three `U`, one `S`, one `L`), `PlaySim.enterStore/tickStore/applyStorePurchase`, overlay in `src/game/scenes/storeOverlay.ts`. - `LearnScene.toggleUpgrade` → `LearnSim.toggleUpgrade(id)` swaps `learnUpgrades.owned`.

## Approach

### Phase 1: domain model (no behavior change yet)

1. `src/domain/upgrades.ts`
   - Rename the current union to `BaseUpgradeId`; add `EnhancedUpgradeId = \`${BaseUpgradeId}Plus\``; `UpgradeId = BaseUpgradeId | EnhancedUpgradeId`.
   - Split the def type: `EffectFields` (all current optional effect fields), `EnhancedOverride = Partial<EffectFields> & { description: string }`, `BaseUpgradeDef = { id: BaseUpgradeId; label; description; storePrice; school; enhanced: EnhancedOverride } & EffectFields`, `UpgradeDef` = either form (`id: UpgradeId`, plus `baseId: BaseUpgradeId`, `enhanced: boolean`).
   - `BASE_UPGRADE_DEFS` (existing rows plus `enhanced`), then `UPGRADE_DEFS = [...base, ...base.map(toEnhancedDef)]` where `toEnhancedDef` = `{ ...base, ...base.enhanced, id: base.id + "Plus", label: base.label + "+", baseId, enhanced: true }` (an override of `onPowerPellet` replaces the whole object, so write it out in full).
   - `ALL_UPGRADE_IDS` = base ids only. Add `ENHANCED_UPGRADE_IDS`.
   - New pure helpers: `baseIdOf(id)`, `enhancedIdOf(baseId)`, `isEnhancedId(id)`, `hasUpgrade(owned, baseId)` (true for either form), `eligibleUpgrades(owned)` (base ids with neither form owned), `enhanceableUpgrades(owned)` (owned non-`Plus` ids), `enhanceUpgrade(state, baseId)` (replace in place; no-op if not owned or already enhanced), `carryEnhancement(outgoingId, incomingBaseId)` (returns incoming id in the outgoing's form).
   - `grantUpgrade`/`revokeUpgrade`: operate on exact ids but `grantUpgrade` is a no-op when `hasUpgrade(state.owned, baseIdOf(id))`; `revokeUpgrade(state, baseOrPlusId)` removes whichever form is owned.
   - `grantLivesForUpgrade(id)` already reads `grantLives`; add `enhanceGrantLives(baseId) = grant(Plus) − grant(base)`.
2. Replace each hard-coded `owned.includes("<id>")` with `hasUpgrade(owned, "<id>")` (list in Today's world). `LearnScene` `ownedUpgrades.includes(row.id)` becomes `hasUpgrade(...)`.
3. `src/domain/seenRecord.ts`: `withSeenUpgrade` stores `baseIdOf(id)`; `parseSeenRecord` keeps using `ALL_UPGRADE_IDS` (base).
4. Tests: `upgrades.test.ts` (new helpers, derived defs exist for every base id, `ALL_IDS` unchanged, every enhanced def `label` ends in `+`), `seenRecord.test.ts` unchanged counts.

## Failure behavior

- Enhancing a target no longer owned: re-pick; none left → `NOTHING TO ENHANCE`, no charge.
- `E`/`S`/`U` tiles omitted (not shown disabled) when there is nothing to enhance/trade/offer.
- Fruit side-by-side with no free same-row cell: that spawn is skipped.
- Fruit Power conversion with no eligible pellet, Recall with fewer eligible ghosts than its count: no-op for the missing part.
- Wall Pass loop ending inside a wall: existing snap to nearest walkable.
- Unknown `?enableUpgrade=` ids stay ignored; `Plus` ids are valid.
